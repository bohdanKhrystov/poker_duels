Sign in

What the account screen's Sign in button opens — the one door to this form, offered only while the browser holds no live session (ADR-0083 §3). Two fields and one refusal that never says which one was wrong (ADR-0027 §6), plus the one link out: to the password nobody remembers.

The form

miro
••••••••

Sign in titles both this card and the submit button — SIGN_IN_HEADING and SIGN_IN_LABEL, two constants sharing one string (account-text.ts). Handle and Password are HANDLE_LABEL and PASSWORD_LABEL, same module. Forgot your password? is FORGOT_PASSWORD_LABEL (recovery-text.ts) — SignInForm.tsx does not render it yet, so this card draws the gap the next UAT round should catch.

When it refuses

That handle and password do not match an account.

miro
••••••••

SIGN_IN_REFUSED (account-text.ts) is the one sentence SignInForm.tsx shows for a wrong password and for a handle no account holds alike — the server makes the two indistinguishable on the wire (ADR-0027 §6), so no second, field-naming refusal is drawn here. The typed fields keep what was entered; the component's outcome state never clears them.

The route out

→

Reaches ForgotPasswordForm.tsx, whose own heading transcribes this same FORGOT_PASSWORD_LABEL (recovery-text.ts). What is past that door — a mailed link, then #/verify or #/reset — is a card of its own; no mail ever arrives in review (ADR-0031 §7), so this one draws the door and stops there.
