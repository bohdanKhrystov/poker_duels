## Goal

Prettier sorts Tailwind class lists using this project's own theme, and still opens neither
`src/protocol/protocol.gen.ts` nor the vendored token sheet.

## Files

| File | Action |
| --- | --- |
| `web-client/package.json` | modify |
| `web-client/package-lock.json` | modify |
| `web-client/.prettierrc` | create |

The lockfile is regenerated by npm and does not count towards the line estimate.

## Scope

- `npm install -D prettier-plugin-tailwindcss` — the last of the three packages `ADR-0026` names,
  held back by `TASK-030101` until a stylesheet existed for it to read.
- `web-client/.prettierrc`, the client's first Prettier config file:

  ```json
  {
    "plugins": ["prettier-plugin-tailwindcss"],
    "tailwindStylesheet": "./src/styles/app.css"
  }
  ```

  `tailwindStylesheet` is how the plugin finds a Tailwind 4 theme — there is no
  `tailwind.config.js` to point `tailwindConfig` at, and without it the plugin sorts against
  Tailwind's defaults, which this project deleted. The path is relative to this file.
- No other Prettier option. Every file in the client is already formatted under the defaults, and a
  `printWidth` or `singleQuote` here would reformat files belonging to tickets already merged.
- Run `npm run format` once so `.prettierrc` and `package.json` are themselves clean.
- `.prettierignore` is not edited. Its by-path exclusions — among them the generated protocol file
  and the vendored token sheet — already cover the new plugin, because Prettier applies the ignore
  file before any plugin sees a path. The verify block proves that rather than assuming it.

## Out of scope

- Sorting anything. No `.tsx` gains a class in this ticket; `TASK-030208` is the first file written
  under the sorter.
- `prettier.config.js`, `.editorconfig`, an `overrides` block.
- A `// prettier-ignore` or `/* eslint-disable */` header in `src/protocol/protocol.gen.ts`.
  `ADR-0026` forbids it by name: those bytes belong to the Kotlin emitter and any header it did not
  write fails `verifyProtocolTypes`. Ignore by path is the only mechanism here.

## Proof

The trap is a plugin that loads but reads the wrong theme — it still sorts, so a naive "did it
sort?" check passes while the ordering is Tailwind's defaults rather than ours.

| Command | Proves |
| --- | --- |
| the `printf … \| prettier --stdin-filepath` pipe | the plugin is loaded **and** reading `app.css`. `p-5 bg-surface text-body` sorts to `bg-surface p-5 text-body` only when the plugin knows `--text-body` is this project's font-size token; with `tailwindStylesheet` missing it emits `bg-surface text-body p-5` and this command fails |
| `prettier --list-different .` never names `protocol.gen.ts` | the new plugin did not widen what Prettier visits |
| `prettier --write src/styles/tokens.css` then `cmp` | the writing formatter, aimed at the vendored sheet, still moves no byte |
| `npm run format:check` and `npm run check` | nothing already in the tree was reformatted by the plugin's arrival |

Watch it fail: delete the `tailwindStylesheet` line, re-run the `printf` pipe, and the output comes
back in the other order. Restore it and say in the PR what the wrong order was.
