## Goal

`tailwindcss` and `@tailwindcss/vite` install from the committed lockfile, and the plugin is
registered in `vite.config.ts` so that `vite build` loads and runs it.

## Files

| File | Action |
| --- | --- |
| `web-client/package.json` | modify |
| `web-client/package-lock.json` | modify |
| `web-client/vite.config.ts` | modify |

The lockfile is regenerated by npm, never hand-edited, and does not count towards the line estimate.

## Scope

- `npm install -D tailwindcss @tailwindcss/vite` from `web-client/`. Install the current stable of
  each and commit whatever the lockfile resolves — `ADR-0026` names the packages, not versions, and
  `TASK-030101` set the rule that the lockfile is the pin.
- `vite.config.ts` gains the import and the plugin:

  ```ts
  import tailwindcss from "@tailwindcss/vite";
  ...
  plugins: [react(), tailwindcss()],
  ```

  Nothing else in the file moves. `server.proxy` and `test` stay exactly as they are — two merged
  tests in `src/dev-proxy.test.ts` read `server.proxy` out of this object and must keep passing
  unchanged.
- `@tailwindcss/vite` declares `vite: ^5.2.0 || ^6 || ^7 || ^8` as a peer, and the client is on
  Vite 5. If `npm install` prints a peer warning, report the resolved versions in the PR rather than
  bumping Vite — the Vite major is `ADR-0026`'s and not this ticket's to change.

## Out of scope

- `prettier-plugin-tailwindcss` and `.prettierrc` — `TASK-030207`. The plugin needs the finished
  stylesheet to read, and it does not exist yet.
- Any stylesheet. Nothing in this ticket writes `@import "tailwindcss"`; the plugin is inert until
  `TASK-030204` gives it a file with that line, and that is deliberate — it keeps the install and
  the wiring in separate diffs.
- Upgrading Vite, Vitest or any other dependency.

## Proof

There is no CSS yet, so the observable claim is narrow and the assertions match it exactly:

| Command | Proves |
| --- | --- |
| `npm ci` | the lockfile is committed and installs both packages on its own, as CI will |
| the `node -e` check on `devDependencies` | both packages are declared, not merely present transitively |
| `grep 'tailwindcss()' vite.config.ts` **with** `npm run build` | not link text: `vite build` loads `vite.config.ts`, so if the call is written and the package is not resolvable the build throws. The grep says the call exists; the green build says it resolved and ran |
| `Tests 10 passed (10)` | the two `dev-proxy` tests still read the config they expect — a plugin added to the wrong key would show up here |

Watch it fail: rename the import to a package that does not exist and run `npm run build`; Vite
fails to load the config. Restore it.
