## Goal

A `HandLog` survives being written down and read back with nothing lost, and a log written under
a version this build does not know is rejected loudly rather than misread.

## Blocked on DEC-006

**Do not implement this ticket.** It is registered in
[`docs/adr/README.md`](../../docs/adr/README.md) as `DEC-006` and waits on a human decision:

> `poker-engine` may not take a dependency — not on kotlinx.serialization, not on Jackson, not
> on anything ([`docs/architecture.md`](../../docs/architecture.md), and the
> `checkNoDependencies` task that enforces it). So where does log serialisation live, and what
> is the format?
>
> 1. **Hand-written inside `poker-engine`.** A line-oriented text format with a version header,
>    written and parsed by hand. No new module, no new dependency, and the format is testable
>    with the engine's own tests — but every event type added later needs a writer branch and a
>    parser branch kept in step by hand, forever.
> 2. **A new module that depends on the engine** — `poker-serialization`, free to use
>    kotlinx.serialization. Far less hand-written code and a format other tools can read — but
>    it adds a module the architecture's module list does not currently contain, and it makes
>    the engine's own tests unable to round-trip their own logs.
> 3. **Neither: the log is not serialised in this epic**, and `EPIC-02` decides the format when
>    it decides how a match is stored in PostgreSQL. Cheapest now, and it leaves the story's
>    "a log survives being written to disk" acceptance criterion unmet.
>
> The answer binds `EPIC-02` (stored matches), `EPIC-03` (a replay viewer) and the module graph,
> so it is not a ticket-level choice. The engine-internal half of this story — `HandLog`,
> `replayHand` and the replay identity property — ships regardless and does not wait on it.

Once answered, this ticket is **re-split** by the splitter into at least a writer, a reader, a
version-rejection ticket and a round-trip property ticket. The sketch below is a shape, not a
sized unit.

## Scope (provisional)

- The written form carries `HAND_LOG_VERSION`, the seed and the whole header, because a log
  without its seed is not replayable.
- Round trip: `read(write(log)) == log` for every `GameEvent` subtype and every `PlayerAction`
  subtype, asserted over logs generated by `playRandomHand`.
- A log whose version is unknown to this build is rejected with an error naming the version it
  found and the version it expected — never read on a best-effort basis.
- A log whose version is *older and known* is either read correctly or rejected explicitly. Which
  of the two is itself part of `DEC-006`: option 1 makes migrations hand-written code.
- Reading a truncated or malformed log reports the position it failed at.
